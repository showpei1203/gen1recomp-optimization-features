# SoulGold M6A2 FIX2 — Timing / Audio / Native Presentation Preservation Authority

Date: 2026-09-03
Branch: `feature/soulgold-showdown-m6a2`

## Runtime evidence that triggered FIX2

AYN THOR user runtime booted the real mGBA/SoulGold path after M6A2 FIX1. The remaining device-level defects were:

1. Audio contained crackle/noise and sounded lower-pitched than normal.
2. Original SoulGold Pokémon-related menu slide presentation appeared absent or visually collapsed.

These are treated as frontend timing/presentation regressions, not as permission to redesign SoulGold presentation.

## Root cause addressed

The M6A2 FIX1 Android frontend called one `retro_run()` from every Android `Choreographer` display callback and drained audio into a non-blocking `AudioTrack.write()` without retaining any unwritten tail.

That design incorrectly made the emulator clock depend on Android display refresh and could discard PCM samples on partial non-blocking writes.

## FIX2 architecture

- mGBA-reported `retro_system_av_info.timing.fps` is the authoritative emulation cadence.
- A dedicated emulation thread advances `retro_run()` from a monotonic clock.
- Android display VSYNC only presents the latest completed framebuffer; it never advances gameplay/emulation time.
- A dedicated audio consumer drains the native PCM queue and uses `AudioTrack.WRITE_BLOCKING` until every drained sample is accepted.
- Native audio telemetry records generated, drained and overflow-dropped sample counts.
- Runtime report records emulation frames, display callbacks/FPS, PCM generated/drained/written/dropped, partial writes, write errors and queue depth.
- Original SoulGold menu/battle animation timing is preservation authority. Android frontend must not intentionally replace, shorten or suppress those transitions.

## Regression rules

- **R-SD-144 CORE_CLOCK_IS_MGBA_TIMING_NOT_ANDROID_VSYNC**: Android display refresh must never determine how often `retro_run()` advances.
- **R-SD-145 AUDIO_DRAIN_MUST_PRESERVE_EVERY_DRAINED_SAMPLE**: Once PCM samples leave the native queue, the frontend must retain/retry until AudioTrack accepts them or a real error is recorded.
- **R-SD-146 AUDIO_DROP_ACCOUNTING_IS_MANDATORY**: Native queue overflow drops, Java partial writes and AudioTrack write errors must be separately observable.
- **R-SD-147 ORIGINAL_SOULGOLD_UI_PRESENTATION_MUST_BE_PRESERVED**: Party/Summary/menu/battle transitions generated by the ROM remain native presentation authority and must not be intentionally collapsed by the Android frontend.
- **R-SD-148 DISPLAY_REFRESH_MAY_REPEAT_OR_SKIP_PRESENTATION_FRAMES_BUT_MUST_NOT_CHANGE_EMULATION_TIME**: 60/90/120 Hz device display behavior may repeat the latest framebuffer, but gameplay/audio timing follows mGBA only.

## Acceptance boundary

Static/CI build success is not THOR runtime PASS. FIX2 requires device validation of:

- normal-pitch clean audio,
- stable gameplay speed,
- original Pokémon menu slide/transitions visibly preserved,
- no crash during normal play,
- timing report with `audio_dropped_samples == 0` and no persistent AudioTrack write errors under representative play.

Showdown Android compositor integration remains deferred until this base runtime timing is stable.
